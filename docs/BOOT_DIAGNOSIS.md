# 부팅·예기치 않은 종료 조사 (2026-11-02)

## 사용자가 확인한 조건

- ESP32 SD카드만 연결하고 USB-C를 뺀 시험: 검은 화면이 발생한 적이 있습니다. 해당 부팅 로그에는 Linux와 KDE 실행 이후 DP-1 EDID 읽기 실패 및 RA24 화면 형식 오류가 있습니다. SD카드와의 인과관계는 미확정입니다.
- USB-C 연결 시험: ATX 전원만 켜지고 다음 단계로 진행되지 않는다고 보고됐습니다. 몰렉스와 같은 BC250 USB를 동시 연결한 구성입니다. 사용자는 5.6에서는 괜찮았다고 보고했으며, 동일 조건의 버전 비교는 미완료입니다.
- USB-C 미연결·SD카드 연결 중 원치 않는 종료가 발생했습니다. 로그에는 전원 관리 서비스의 정상 종료 명령이 있지만 사용자는 버튼을 누르지 않았습니다. 요청의 최초 원인은 아직 확인하지 못했습니다. 터치 오인식은 가설입니다.
- 이후 USB-C를 제외한 정상 종료/부팅 시험은 사용자가 성공을 확인했습니다. 현재 SD는 정상 인식되며 관리자 화면도 SD에서 제공됩니다.

## 임시 진단 조치

PC의 `/etc/bc250-power-manager/block-power-actions` 파일이 있으면 companion은 인증된 shutdown/reboot 요청도 HTTP 423으로 거부합니다. 이 장치에는 해당 차단 파일이 설치되어 있습니다. 모니터링과 PC 자체의 정상 종료는 유지됩니다. 이 파일은 다른 사용자의 설치에 자동 생성되지 않습니다.

종료·재부팅 API 요청은 출발지 IP, 동작, 처리 결과를 journal에 기록합니다. PIN·토큰·인증 헤더는 기록하지 않습니다. 원인을 해결하고 의도적으로 차단 파일을 제거하기 전까지 ESP32 정상 종료/재부팅 버튼은 사용할 수 없습니다. 원인 확인 없이 차단부터 해제하지 않습니다.

## 현재 기능 범위

5.8.1은 USB 무선랜을 포함하지 않습니다. 기존 USB H4 Bluetooth 수신기와 USB 모니터링 코드는 유지됩니다. PC Bluetooth 서비스는 케이블 연결을 기다립니다. 이후 사용자가 PC 실행 중 USB-C를 연결했습니다. PC 실행은 유지됐고 CH340이 등록됐으나 HCI 명령 타임아웃으로 Bluetooth 어댑터 초기화는 완료되지 않았습니다. USB를 꽂은 상태의 콜드 부팅은 여전히 미검증입니다.

Wi-Fi OTA의 릴레이 유지 로직은 보존했습니다. 이전 5.7→5.8.1 OTA에서는 PC 부팅 ID 유지와 릴레이 HIGH 복귀를 확인했으나, 이번 정상 부팅 결과가 새로운 OTA 전원 유지 시험을 대신하지는 않습니다.

5.8.3에서는 사용자 요청에 따라 세 USB 기능을 각각 선택하는 시험 메뉴를 추가했습니다. [현재 시험 메뉴](USB_TEST_MENU.md)를 참조하세요. 5.8.1→5.8.3 OTA에서도 PC 부팅 ID 유지와 릴레이 HIGH 복귀를 확인했습니다.
