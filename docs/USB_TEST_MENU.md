# USB 기능 개별 시험 — 5.8.3

관리자 화면의 **연결과 설정 → USB 기능 개별 시험**에서 Bluetooth, USB 모니터링, USB 비상 인터넷을 각각 켜고 끕니다. 기본값은 모두 OFF이며 ESP32 재부팅·OTA 뒤에도 모두 OFF로 돌아갑니다. 설정 ON과 실제 수신/PC 연결 상태는 구분해서 표시합니다.

## 시험 순서와 조건

1. USB-C를 뺀 상태의 정상 부팅을 먼저 확인합니다. USB 연결 상태의 콜드 부팅 문제는 아직 미해결입니다.
2. PC가 켜진 상태에서 케이블을 연결하고 USB 블루투스만 켭니다. 운영체제에서 어댑터가 준비되는지 확인합니다.
3. USB 모니터링을 켜고 ‘모니터 수신: USB’로 바뀌는지 확인한 뒤 끕니다. 다시 Wi-Fi 수신으로 돌아와야 합니다.
4. 비상 무선랜을 켜고 PC 연결 준비와 실제 IPv4 TCP/UDP 연결을 별도로 확인합니다. 실물 인터넷 동작은 검증 전이며 정상 동작을 보장하지 않습니다.
5. 블루투스를 끄려면 다른 두 기능을 먼저 끕니다. 모두 같은 HCI USB 통신 경로를 사용하기 때문에 이 의존성은 임의로 해제할 수 없습니다.

각 기능은 **릴레이 ON 및 해당 스위치 ON** 조건에서 동작합니다. 릴레이 OFF 또는 OTA 중에는 USB 데이터 기능이 정지합니다. 실제 ATX 전원을 읽는 센서는 없으므로 릴레이 출력 상태를 기준으로 합니다. CH340의 USB Serial 장치 등록 자체는 별도 하드웨어 동작이며 펌웨어 스위치가 장치 자체를 물리적으로 분리하지는 않습니다.

## PC 연결 도구

기존 Bluetooth companion을 설치한 Linux amd64에서 다음 도구로 갱신합니다. 기존 동작 설정과 원격 종료 임시 차단 파일은 보존합니다.

```bash
sudo python3 host/install_emergency_network.py --activate-host
# 오프라인 설치: 공식 tun2socks v2.7.0 ZIP을 미리 준비
sudo python3 host/install_emergency_network.py --activate-host --archive /path/to/tun2socks-linux-amd64.zip
```

설치기는 공식 실행 파일 ZIP의 SHA-256을 검증하고, 기존 PC 파일을 `/var/lib/bc250-esp-network/` 아래에 백업합니다. 모니터링 기능을 켰을 때만 root 전용 런타임 마커에 따라 USB 표본을 전송합니다. 비상 인터넷 서비스는 기본 inactive/disabled이며, 명시적인 시작 요청 때만 임시 네트워크 인터페이스를 만듭니다. 중지하면 자신이 만든 UUID의 경로/프로필만 정리합니다. 유선 LAN metric보다 낮은 우선순위(metric 900)를 사용합니다.

USB 비상 인터넷은 IPv4 TCP/UDP, 최대 3개 소켓, UDP 1472바이트 한도입니다. 물리 WLAN 검색, IPv6, ICMP/ping은 제공하지 않습니다. USB UART 921600 baud를 공유하므로 대용량 전송용이 아닙니다. TLS는 바이트 그대로 중계합니다. 로컬 SOCKS 포트는 127.0.0.1에만 바인딩합니다. 자체 비상 인터넷을 경유한 OTA는 거부하며 직접 LAN/같은 공유기의 휴대폰에서 업데이트합니다.

## 전원 유지와 조사 상태

5.8.1→5.8.3 Wi-Fi OTA에서는 PC 부팅 ID 유지와 릴레이 HIGH 복귀를 확인했습니다. GPIO 순간 파형은 측정하지 않았습니다. 실제 재부팅·USB 부팅·새 케이블 조합의 보장은 아닙니다.

예기치 않은 종료를 조사하기 위한 PC의 원격 종료/재부팅 API 차단은 계속 유지합니다. 요청 출처와 결과는 journal에 남기며 비밀번호나 토큰은 기록하지 않습니다. [부팅 진단](BOOT_DIAGNOSIS.md)을 함께 확인하세요.
